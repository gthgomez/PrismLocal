# Inference evidence contract

This file defines the evidence rules for PrismLocal inference work. It is the
contract every run record, disposition and benchmark claim must satisfy; it is
not itself evidence that any test has run.

## 1. Purpose and the three evidence layers

Claims about inference behaviour and performance must be traceable to one of
three layers, and must never silently upgrade between them:

- **S — source-derived.** Facts read from the repository at a pinned revision
  (gitlink, patch hash, build flags, code paths). Produced by
  `scripts/inference/capture-baseline.sh`.
- **D/I — declared / inferred.** A planned or requested configuration and the
  reasoning that predicts an effect. Declared values are *requests*, not results.
- **B — measured.** A recorded observation from an executed run: counters,
  timings, correctness outcomes, exit codes.
- **H — hypothesis.** An explanation or optimization idea that has not been
  tested. A hypothesis is never reported as a result.

Every statement in a report must be labelled with its layer. A source-derived or
declared value may motivate a run; it cannot substitute for the measured result.

## 2. Artifact layout

```
research/inference/
  baseline.lock.json   # generated provenance freeze (see §1 S)
  experiments/         # per-mission design/plan records (declared intent)
  results/             # per-run measured records (layer B)
  capabilities/        # per-device/backend capability observations
```

Keep private benchmark data and model files out of Git (`*.gguf`, `*.bin`,
`*.onnx`, `*.tflite`, raw prompt corpora, device dumps). Commit only manifests,
scripts and redacted summaries. Never commit a model file to satisfy a hash.

## 3. Required fields for a run record

Each `results/` record must carry, at minimum:

- **Identity:** model id, model SHA-256, quantization, chat template id/hash.
- **Device:** device model, SoC, RAM class, OS/API level, driver/GPU version.
- **Backend:** backend requested, backend applied, FA/KV/context/batch settings.
- **Plan:** requested, applied and observed plan as three distinct fields.
- **Execution:** exact command, exit code, start/end UTC timestamps.
- **Outcome:** test status and disposition (see §5), with failure causes.

## 4. Requested vs applied vs observed; null policy

- A requested value is never presented as observed. `requested: vulkan` with
  `observed: cpu_fallback` is a finding, not a success.
- Unavailable counters (GPU memory, energy, thermal) are `null` with an
  availability reason. Never zero-fill: zero is a measurement, `null` is not.
- Never infer a value that was not captured; leave it `null` and mark the run's
  completeness. Unknown is preserved, not smoothed away.

## 5. Disposition and test status vocabulary

Disposition (one per experiment/run): **RETAIN / MODIFY / REJECT / BLOCKED**.
Test status: **PASS / FAIL / BLOCKED / NOT_RUN**.

A missing toolchain, model, device or permission is **BLOCKED**, never PASS.
"No failure observed" from a run that never executed is NOT_RUN, not PASS.
A rejected or blocked experiment may satisfy an information dependency; it never
becomes a winning runtime setting.

## 6. Benchmark cohort separation

- Synthetic fixtures are explicitly ineligible for comparison and must be
  labelled as such; they are validator test data, not phone performance.
- Chat records, thermal records and synthetic records are separate cohorts and
  must not be mixed in one ranking or aggregate.
- Invalid or unknown-terminal runs are excluded from winners but preserved as
  failures. Cohort membership and eligibility are recorded per row.

## 7. Command-log format for the capture script

Record the command verbatim, the resolved working tree (HEAD SHA + branch), the
exit code, and whether the run was a dry run or an applied write. The baseline
capture is dry-run by default:

```sh
scripts/inference/capture-baseline.sh            # prints JSON to stdout, writes nothing
scripts/inference/capture-baseline.sh --apply    # writes research/inference/baseline.lock.json
```

`baseline.lock.json` is generated by that script and must not be hand-edited.
Changing it means re-running the capture at the new pinned revision.

## 8. Correctness gates

All inference changes must pass the relevant correctness gates **G01–G16**
defined in `PrismLocal_Inference_Roadmap.md` §24 (provenance/build, lifetime,
lossless stream, Unicode, sampling, template/budget, prefix/cache, shift/context,
load contract, memory/validation, backend math, KV quality, speculation, Android,
auxiliary capabilities, benchmark integrity). An emulator-only pass cannot
certify accelerator math. The gates are not restated here; cite the gate id and
attach the failing fixture, passing fixture and applied-plan evidence required
in that section.
